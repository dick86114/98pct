# 今天发什么发版管理平台 - 产品需求文档

## 一、产品概述

### 1.1 产品定位
今天发什么发版管理平台是一款面向软件开发团队的发版流程管理工具，旨在规范化软件发布流程，通过将上线验证工作前置并分散到整个交付周期，避免问题在发版日集中爆发，从而有效降低上线风险与压力，确保发布过程平稳、有序。

### 1.2 目标用户
- 超级管理员（ADMIN）：系统管理员，负责用户管理、数据字典等系统配置
- 项目经理（PM）：流程发起者与总协调人，负责发版流程管理
- 开发人员（RD）：负责代码开发与变更
- 测试人员（QA）：负责功能测试与验收
- 产品经理（PO）：负责业务验收
- 数据库管理员（DBA）：负责数据库变更
- 运维人员（OP）：负责部署与运维

### 1.3 核心价值
- 流程标准化：统一发版流程，减少人为失误
- 责任明确化：各角色职责清晰，可追溯
- 风险可控化：检查清单机制，确保每个环节都经过验证
- 协作高效化：多角色在线协同，实时同步进度

## 二、功能模块

### 2.1 用户管理模块

#### 2.1.1 用户注册与登录
- 支持用户名/手机号登录
- JWT Token 认证机制
- 登录状态持久化

#### 2.1.2 用户管理（ADMIN 专属）
- 查看所有用户列表
- 创建新用户
- 编辑用户信息（姓名、角色、联系方式）
- 批量导入用户（Excel 格式）
- 用户角色分配（支持多角色）

#### 2.1.3 角色权限
| 角色 | 权限说明 |
|------|----------|
| ADMIN | 系统管理权限，包括用户管理、数据字典管理、查看所有发版记录 |
| PM | 发版管理权限，创建发版、管理自己发起的发版、推进发版流程、确认检查清单 |
| RD | 创建发版、填报开发内容、确认开发相关检查项 |
| QA | 填报测试内容、确认测试相关检查项 |
| PO | 填报验收内容、确认产品相关检查项 |
| DBA | 填报数据库变更、确认 DBA 相关检查项、填报执行结果 |
| OP | 填报运维内容、确认运维相关检查项 |

### 2.2 发版管理模块

#### 2.2.1 发版列表
- 查看所有发版记录
- 按状态筛选（草稿、进行中、已完成、已回滚）
- 按平台筛选
- 快速查看发版进度

#### 2.2.2 创建发版
- 填写版本号（唯一）
- 填写发版描述
- 选择目标平台
- 设置计划发版时间
- 分配参与成员

#### 2.2.3 发版详情
- 查看发版基本信息
- 查看/编辑发版内容
- 查看团队成员进度
- 查看/上传相关文档
- 执行检查清单确认
- 阶段流转控制

### 2.3 三阶段流程管理

#### 2.3.1 准备阶段（PREPARATION）
**目标**：确保发版内容已完整验证，具备上线条件

**各角色任务**：

| 角色 | 任务内容 |
|------|----------|
| RD | 填报变更内容（代码变更、数据库变更、配置变更）、完成自测检查清单 |
| QA | 上传测试用例、完成功能测试、提交测试报告、完成测试检查清单 |
| PO | 完成产品验收、提交验收报告、完成产品检查清单 |
| DBA | 审核数据库变更脚本、确认脚本可执行、完成 DBA 检查清单 |
| OP | 准备备份方案、提交回滚方案、完成运维检查清单 |
| PM | 确认各方准备就绪、确定发版时间、通知相关方、完成 PM 检查清单 |

**检查清单项目**：
- RD 自查：自测发版内容、移动端、关联模块、填报变更内容
- QA 自查：上传测试用例、功能测试、移动端测试、关联模块测试、提交测试报告
- PO 自查：核对需求范围、核心流程、测试问题、界面显示、移动端功能
- DBA 自查：审核数据库变更、确认脚本运行正常
- OP 自查：备份工作、回滚方案、回退步骤确认
- PM 自查：开发准备、测试通过、PO 确认、DBA 评审、回滚准备、发版时间、通知发送

#### 2.3.2 实施阶段（IMPLEMENTATION）
**目标**：执行发版操作，完成代码部署和数据库变更

**PM 统一确认清单**：
- 数据库备份完成（附截图）
- 代码/配置备份完成
- 已通知客户准备开始发版
- DBA 执行 SQL 脚本，确认执行无报错
- 运维/开发执行代码部署，确认部署过程无误

**DBA 执行结果填报**：
- 实际执行时间
- 执行人信息
- 执行结果详情
- 回滚情况说明
- 备注信息

#### 2.3.3 验证阶段（VERIFICATION）
**目标**：验证发版结果，确认系统正常运行

**PM 统一确认清单**：
- 运维/开发确认服务启动成功
- 开发确认应用日志无异常 ERROR
- 本次发版更新功能正常
- 核心业务流程正常
- 提交正式环境测试报告

#### 2.3.4 完成/回滚
- **完成**：所有验证通过，发版成功
- **回滚**：验证失败，执行回滚方案

### 2.4 内容填报模块

- 执行结果详情

## 三、非功能需求

### 3.1 性能要求
- 页面加载时间 < 2 秒
- API 响应时间 < 500ms
- 支持 50+ 并发用户

### 3.2 安全要求
- 密码加密存储（bcrypt）
- JWT Token 认证
- 敏感操作需授权验证

### 3.3 兼容性要求
- 支持主流浏览器（Chrome、Firefox、Safari、Edge）
- 支持移动端响应式布局
- 支持 iOS/Android 移动浏览器

### 3.4 可用性要求
- 7x24 小时可用
- 数据定期备份
- 支持 Docker 容器化部署

## 四、技术架构

### 4.1 技术栈
- 前端：Next.js 14 + React 18
- 后端：Next.js API Routes
- 数据库：PostgreSQL
- ORM：Prisma
- 认证：JWT
- 部署：Docker

## 五、数据模型

### 5.1 核心实体
- User（用户）
- Release（发版）
- ReleaseMember（发版成员）
- MemberContent（成员填报内容）
- DbChange（数据库变更）
- ConfigChange（配置变更）
- Checklist（检查清单）
- Document（文档）
- Dictionary（数据字典）

### 5.2 实体关系
```
User ──1:N──> Release（创建者）
User ──1:N──> ReleaseMember
Release ──1:N──> ReleaseMember
ReleaseMember ──1:1──> MemberContent
MemberContent ──1:N──> DbChange
MemberContent ──1:N──> ConfigChange
Release ──1:N──> Checklist
Release ──1:N──> Document
```
